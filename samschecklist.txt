SAMS WEB REDESIGN CHECKLIST
===========================================================================
Goal: make the web system (Student, Supervisor and Admin portals) look and
behave like the mobile app, and fix broken UI / weak UX.
Built from a scan of the web repo (samss-main) and mobile repo (sams-mob-app).
Findings come from the code only. No pages were rendered, so do the visual
QA in section 7.

---------------------------------------------------------------------------

WHAT THE SCAN FOUND
---------------------------------------------------------------------------
A design system already exists (assets/css/sams-design-system.css, Inter +
Poppins), but the only 6 pages linking it are public/auth pages (login,
index, register, register1-3). NONE of the 35 portal pages use it. Each
carries its own inline CSS (up to 981 lines, 50-120 hardcoded hex colors),
so changing the tokens alone will not restyle them. Each page has to be
migrated.

0. DECIDE FIRST
---------------------------------------------------------------------------
[x] Adopt the mobile palette as the single source of truth (navy #061D5A,
    gold #F4B333, semantic colors from the table above).
[x] Dark mode: mobile screens are light-only, but web has sams-dark-mode.css
    on 20 pages. Either remove it, or rebuild it on the new tokens. Do not
    keep it half-matching.
[x] Type scale: keep Inter (UI) + Poppins 700/800 (headings) as on mobile,
    but use desktop sizes (body 14-15px). Mobile's 11-13px is too small for
    a desktop screen.
[x] One shell for all three roles: navy sidebar, gold active indicator, navy
    page-header band, white cards (the web version of mobile's navy tab bar
    and header).
[x] One icon source: includes/icon.php (178 inline SVGs are pasted across
    pages today). Use outline icons that match mobile's Material style.

Decision lock: the palette is navy/gold first, the shell is shared across
roles, and typography stays Inter + Poppins with desktop sizing. Dark mode is
not kept as a partial legacy theme; it must either be removed or rebuilt on
new tokens before page migration.

2. SHARED SHELL (SIDEBAR AND TOPBAR)
---------------------------------------------------------------------------
FOUND: admin uses admin/_sidebar.php; supervisor/ and students/ have no
sidebar partial, so nav markup is repeated in each page. Sidebar
backgrounds also differ between portals.

[x] Create one includes/sidebar.php driven by role (admin / supervisor /
    student) and use it in every portal page.
[x] Create one topbar partial: page title + subtitle, notification bell,
    user chip.
[x] Sidebar style: navy background, white text, gold active indicator,
    clear hover and focus states.
[x] Same nav conventions in all roles: label wording, icon style, logout
    position.
[x] Responsive: sidebar becomes a drawer with hamburger at tablet width and
    below; page content never scrolls sideways.

Shell note: the shared sidebar and topbar partials are in place and parse
cleanly; they establish the common layout contract for the portal migration.

3. SHARED COMPONENTS
---------------------------------------------------------------------------
[ ] Cards and stat cards matching mobile (white, 1px border, radius 16,
    soft shadow).
[ ] Buttons: primary (navy), accent (gold background with navy text),
    secondary, danger. Add disabled and loading (spinner) states and block
    double-submit. Never use gold text on white (low contrast).
[ ] Status pills: one shared mapping used everywhere. Suggested:
    Present / Completed / Accepted / Active = success;
    Pending / Late = warning;
    Absent / Declined / Rejected = danger;
    Scheduled / Info = info.
[ ] Tables: sticky header, row hover, scroll wrapper on small screens,
    consistent action buttons.
[ ] Forms: visible labels, required marker, inline error and help text,
    focus ring, password show/hide.
[ ] One modal component (Esc and backdrop close, focus trapped). Use it for
    the availability-note modal, excuse-note review, confirmations.
[ ] Toasts / flash messages in one style for success, error and info.
[ ] Empty states like mobile (icon circle, title, one-line hint, action
    button) on every list and table.
[ ] Loading states: spinner or skeleton for async panels (attendance stream,
    reports, dashboard stats).
[ ] List toolbars: the same search + filter + pagination bar on all admin
    lists.
